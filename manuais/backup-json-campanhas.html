Manual WMK: salvamento, backup JSON e campanhas

Walney Moreira Klein — walneyk@hotmail.com · 23/11/2026 · Branch develop

ATENÇÃO: seu navegador pode apagar saves locais. Não considere o localStorage um backup. Exporte o JSON periodicamente e guarde uma cópia em pasta externa ou nuvem de sua escolha.

1. Como fazer o backup completo

  1. Abra Configurações → Backup JSON no mesmo endereço em que joga (ex.: localhost:5500 ou GitHub Pages).
  2. Clique em Atualizar lista para localizar os registros WMK no navegador.
  3. Deixe todos selecionados, ou desmarque o que não deseja exportar.
  4. Clique EXPORTAR BACKUP JSON.
  5. Guarde o arquivo WMK-Backup-AAAA-MM-DD.json fora do navegador. Recomenda-se guardar também uma cópia em outro disco ou nuvem.

Para outros computadores, leve o arquivo JSON e importe no novo navegador. É necessário abrir a página pelo mesmo domínio/origem para acessar registros anteriores. Como localhost:5500 e localhost:4173 são origens distintas, têm armazenamentos separados.

2. Como restaurar sem perder sua evolução atual

  1. Antes de restaurar, faça um backup do estado atual.
  2. Clique em Escolher arquivo e selecione o JSON exportado pelo menu.
  3. Verifique a data do arquivo e a quantidade de registros.
  4. Pressione RESTAURAR BACKUP e confirme o aviso.
  5. Reabra o jogo e os editores para recarregar os dados.

Importação mescla as chaves presentes no arquivo, sobrescrevendo os valores dessas chaves. Chaves locais não incluídas permanecem. Não há fusão automática entre moedas ou inventários de duas versões diferentes.

3. O que entra, o que fica de fora

Entra quando armazenado localmenteNão entra automaticamente
Saldo e histórico W$; itens adquiridosGLB do Blender que está apenas no computador
Mapas JSON salvos no navegador; prefabsPNG de skins/referências externos, vídeos ou WAV externos
Configuração de Cidade Viva salva como registro WMKMapa que só foi exportado como arquivo sem cópia no localStorage
Layouts dos painéis, skins e avatares persistidosDados guardados em outro navegador/domínio/porta

Backups são limitados a 8 MB e 250 registros, com máximo de 2 milhões de caracteres por registro. Dados com nome indicativo de token, senha ou credencial não são exportados. Arquivos grandes devem ser guardados separadamente.

4. JSON de backup: estrutura técnica

{
 "format": "wmk-backup",
 "schemaVersion": 1,
 "createdAt": "2026-11-23T00:00:00.000Z",
 "app": "WMK Zombie Arena",
 "entries": {
   "wmk_wallet_v1": "{\"balance\":500,\"history\":[]}",
   "wmk_shop_inventory_v1": "{\"skin_cyan\":1}"
 }
}

Os valores em entries são strings porque reproduzem precisamente os dados armazenados no navegador. Não há execução de código importado. Cada chave passa por validação de nome e tamanho. O importador mantém uma cópia dos valores existentes para tentar restaurá-los se ocorrer erro de gravação.

5. Cuidados com segurança e desempenho

Não aceite backups de origem desconhecida. Um arquivo pode conter dados manipulados; use apenas arquivos que você exportou ou revisou. A restauração do backup não garante compatibilidade entre versões que alteraram os formatos internos. O armazenamento local não serve como economia segura para multiplayer: em jogos online o servidor deve autorizar compras e recompensas.

6. Campanhas e missões: arquitetura planejada

A campanha terá slots de save e missões JSON, separando definição da missão, estado do mundo e progresso do jogador. Abaixo está um exemplo de formato proposto, ainda não implementado no motor:

{
 "format": "wmk-campaign-save",
 "schemaVersion": 1,
 "slot": 1,
 "campaignId": "ultimo-dia-normal",
 "missionId": "defender-oficina",
 "checkpointId": "oficina-inicio-noite",
 "player": {
   "health": 88,
   "avatarId": "survivor-default",
   "wallet": 920,
   "inventory": ["pistol", "medkit"]
 },
 "world": {
   "mapId": "bairro-zero",
   "timeMinutes": 1190,
   "zombieRule": "night",
   "vehicleStates": []
 },
 "objectives": [
   {"id":"gerador","complete":true},
   {"id":"defender","complete":false}
 ]
}

Missões serão dados declarativos, sem JavaScript arbitrário. O editor validará IDs, gatilhos, condições de vitória/derrota e recompensas. O jogo aplicará eventos por mecanismos internos registrados.

7. Sequência de campanha prevista

  1. O Último Dia Normal: explorar o Bairro Zero antes do surto.
  2. Sinal de Emergência: obter rádio e suprimentos.
  3. Defender a Oficina: instalar barricadas e resistir à primeira noite.
  4. Fuga da Zona Zero: encontrar combustível, veículo e saída.
  5. A Noite do Hospital: enfrentar um zumbi especial e resgatar sobreviventes.

Futuras missões poderão ser compartilhadas com mapa, zumbis e armas próprios, desde que os assets tenham licenças apropriadas.
